# Contributing to Macho ya Mwananchi

Thank you for wanting to help. This project makes claims about how public money
was spent, and people's reputations and livelihoods sit on the other side of
those claims. That shapes how we accept contributions.

**The rule that matters most:**

> **No figure, project, or finding enters this repository without a citation to
> the OAG report and page it came from.** If you cannot cite it, it does not go
> in — however confident you are, and however widely it has been reported.

Everything below is detail on that principle.

---

## Ways to contribute

| | |
|---|---|
| 🐛 **Bug reports** | Open an issue. Include what you did, what happened, and what you expected. |
| 🔐 **Security issues** | **Do not** open an issue — see [SECURITY.md](SECURITY.md). |
| 📊 **Data corrections** | See "Correcting published data" below. This is the most valuable contribution. |
| 🗺️ **Geocoding** | Only 6 of 1,449 projects have coordinates. Cited, verifiable coordinates are very welcome. |
| 🌍 **Swahili translation** | UI strings and error messages. Fluency matters more than code skill. |
| 💻 **Code** | See the workflow below. |

## Correcting published data

If a figure on the platform is wrong, that is a bug of the most serious kind and
we want to know.

- **If you are the person or office named** in a finding: you have a right of
  reply. Email **gevversonkipkoech83@gmail.com**. You do not need a GitHub
  account and you do not have to argue your case in public.
- **If you are a researcher or citizen** who has spotted an error: open an issue
  with the project or finding, what the platform says, what the source actually
  says, and the report name and page number.

We have corrected our own published figures before and documented it — see
[DATA_PROVENANCE.md](DATA_PROVENANCE.md). Corrections are not embarrassing here;
uncorrected errors are.

## Adding a new county or report

Data is **generated by a pipeline, not typed by hand.** Please do not hand-edit
`server/data/seed.js` or `findings.json` — a hand-written entry has no
provenance and cannot be regenerated or audited.

The pipeline lives in `ai-service/pipeline/`:

```
county_pipeline.sh      # fetch + extract a county's OAG PDFs
appendix_county.py      # parse per-project verification appendices
build_national.py       # classify status, emit projects
build_findings.py       # emit cited findings
gen_geography.py        # derive county/constituency coverage flags

# final merge into the production seed (note: lives in server/data/)
server/data/build_production_seed.mjs
```

To add a county, add its slug to `SLUG_TO_COUNTY` in both `build_national.py`
and `build_findings.py`, then run the pipeline, finishing with `server/data/build_production_seed.mjs`
to merge the generated data into the production seed. No other code should need
to change — if it does, that is worth an issue.

Please include in your PR:

- how many projects and findings were produced, and from how many PDFs
- a note if the county's reports are **narrative-only** (no project register).
  This is common and is not a bug — those counties contribute findings only.
- anything the parser got wrong that you had to work around

### Things the pipeline has got wrong before

Worth knowing before you trust its output:

- **OCR corrupts amounts.** `47,428,765,52` naively parsed becomes 4.74 billion.
  `money.py` handles the four observed corruption classes and returns `null`
  rather than a guess. **Never replace a `null` amount with your best guess.**
- **Bank balance tables are not allocation tables.** Nine bank account numbers
  were once ingested as project allocations, producing a "Ksh 1.14 trillion"
  primary school.
- **Partially built is not a ghost project.** Calling a real, half-finished
  project a ghost is a serious accusation. There is a guard for this in
  `classify_status`; do not weaken it.
- **Appendix tables without serial-number columns** used to collapse into a
  single row. Check your row counts look plausible.

## Code contributions

### Setup

Follow the manual setup in the [README](README.md#manual-setup-development).

### Workflow

1. Branch off `main` — `fix/…`, `feat/…`, `data/…`, or `chore/…`
2. Make the change
3. Run the tests (see below) — **hermetically**
4. Open a PR describing what changed and why, and how you verified it

### Running tests

> ⚠️ **`playwright.config.js` defaults to production.** A bare
> `npx playwright test` tests the **live site**, not your changes, and will show
> failures that have nothing to do with your work. Always run hermetically:

```bash
mongod --dbpath /tmp/mym --port 27099 &
cd server && MONGO_URI=mongodb://127.0.0.1:27099/mym npm run seed
DISABLE_RATE_LIMIT=1 PORT=3199 MONGO_URI=mongodb://127.0.0.1:27099/mym node server.js &
cd ../client && npm run build && npx vite preview --port 4199 &
BASE_URL=http://127.0.0.1:4199 SERVER_URL=http://127.0.0.1:3199 CI=true npx playwright test
```

Also run:

```bash
cd server && npm test
python3 tests/guards/test_no_unsourced_answers.py
```

`DISABLE_RATE_LIMIT=1` exists **only** for hermetic test runs. It must never be
set in production.

### Style

There is no linter configured yet (contributions welcome). Match the
surrounding code:

- ES modules throughout; `async/await`, not callbacks
- Routes stay thin — validation, then a model call, then a response
- API responses are `{ success, data, ... }` or `{ success: false, error, code }`
- User-facing error messages are in **Swahili**
- **Comments explain _why_, not _what_.** The codebase documents the reasoning
  behind non-obvious decisions (why `trust proxy` is set, why the vector store
  is committed, why the model is a chain). Keep that up — it is why the project
  is still maintainable.

### Working with the repository

- **`ai-service/venv/` is not tracked.** It was until September 2026 — 16,166
  files. Recreate it locally; do not commit it.
- Stage explicit paths. Historically `git add -A` here swept in hundreds of
  dependency files.
- `ai-service/chroma_db/` **is** committed deliberately — see the note at the
  bottom of `.gitignore`.
- Never commit a real `.env`. Only `.env.example` templates belong in git.

### Touching the AI service

Extra care here — this is the component that talks to citizens in their own
words, and it has fabricated content before.

- Answers must come from **retrieved corpus chunks only**. There is no
  general-knowledge fallback, and reintroducing one will fail CI.
- Do not add hand-written "seed" or "context" text for the model to draw on.
  Four such blobs have been removed from this codebase; one of them named real
  individuals as responsible for fraud and included an invented EACC tracking
  code, and it was on the path actually answering citizens.
- **If you find one such blob, grep for a second copy on the hotter path.**
- Empty or low-relevance retrieval must short-circuit **before** the model call.
- Pin behaviour to the model *chain*, never a single model name.
